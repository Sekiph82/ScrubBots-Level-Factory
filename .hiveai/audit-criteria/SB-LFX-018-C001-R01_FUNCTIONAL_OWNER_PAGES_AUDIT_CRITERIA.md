# SB-LFX-018-C001-R01 — Functional Owner Pages — Audit Criteria

## Retain

R01 must retain:

- exactly eight primary destinations;
- current simple visual hierarchy;
- native title `ScrubBots Factory Studio`;
- compact footer;
- collapsed Technical details;
- legacy capabilities reachable contextually;
- canonical review/publish safety authorities;
- no shadow truth.

## A. Canonical presentation rule

Every owner-page summary must derive read-only from existing canonical records/services/surfaces.

No new independent acceptance, solve, readiness, batch, release, content-version or provider truth store.

Owner mutations must delegate to existing canonical methods/services.

## B. HOME

With canonical fixture/batch data present, HOME must show:

- imported count;
- solved count;
- needs-attention count;
- reviewed count;
- accepted count;
- compact progress;
- thumbnail/grid or equivalent visual item strip;
- Continue Batch.

With no batch, truthful empty state.

## C. CREATE

Require:

- single PNG entry;
- multi-PNG/batch entry;
- artwork preview;
- concise validation/preparation state;
- Generate/Start Batch path;
- Advanced/recipes remain contextual.

Do not mutate source art.

## D. BATCH

Require on the simple page:

- overall progress;
- item list/grid with thumbnail/identity/status;
- success / processing / needs-attention counts;
- eligible retry action;
- resume/recovery path;
- no inferred success.

## E. SOLVE

Require on the simple page:

- artwork/board preview;
- supply columns selector/status for 3/4/5;
- supply summary;
- solver result;
- replay/result state where available;
- official Difficulty V1;
- concise validation state;
- Solve/Re-solve action.

Canonical solver/supply/difficulty services remain authoritative.

## F. REVIEW

Require on the simple page:

- preview;
- supply summary;
- solver result;
- Difficulty V1;
- compact readiness;
- explicit ACCEPT;
- explicit REJECT;
- Compare optional/contextual.

ACCEPT/REJECT must call existing canonical owner-review authority.

QA must never imply acceptance.

## G. LIBRARY

Require:

- search field/action;
- compact filter controls;
- result grid/list with thumbnail/identity/status;
- open/details;
- revisions/reproduce/history contextual.

No persisted fake collection.

## H. PUBLISH

Require the simple page to visibly expose the safe progression:

`Accepted Levels -> Campaign Order -> Preflight -> STAGING -> Production Approval`

Require:

- accepted selected levels;
- order/level numbers;
- current content version when available;
- concise preflight;
- Publish to STAGING;
- separate production approval;
- receipt/status.

All mutation remains delegated to the canonical Release/Content Pipeline authority.

No production approval inference.

## I. SETTINGS

Require compact common admin status/config entry points:

- provider;
- path/runtime;
- cost/credit status where known;
- diagnostics/advanced;
- recovery.

Unknown values stay unknown.

## J. Visual evidence

Capture all eight pages from durable Release runtime at owner desktop scale.

Use deterministic, clearly labeled fixture/canonical data to demonstrate page-specific states.

Do not reuse one generic empty shell as sufficient evidence for all pages.

Screenshots must show:

- HOME batch summary;
- BATCH item/progress view;
- SOLVE supply/solver/difficulty;
- REVIEW readiness + ACCEPT/REJECT;
- LIBRARY results;
- PUBLISH workflow/actions;
- SETTINGS compact admin state.

Final visual disposition may remain `TECHNICAL PASS / OWNER VISUAL REVIEW` until owner approval.

## K. Regression

Require:

- focused owner-page tests;
- legacy capability reachability tests;
- review/publish truth-boundary tests;
- Factory Studio runtime suite;
- durable launcher/runtime smoke;
- Godot parse/import;
- exact previously stalled Route A integration classified and completed;
- complete repository pytest with every collected node accounted for, monolithic or deterministic shards;
- zero unresolved failures;
- compileall;
- diff check;
- secret scan;
- no TASKS edit by builder;
- no audits edit by builder.

No skip/xfail/assertion weakening to hide a regression.

## Outcome

PASS only when A-K close.

Then:

`TECHNICAL PASS / OWNER VISUAL REVIEW`

If owner approves the final screenshots, close:

`PASS / CLOSED`

and only then advance to M17.
