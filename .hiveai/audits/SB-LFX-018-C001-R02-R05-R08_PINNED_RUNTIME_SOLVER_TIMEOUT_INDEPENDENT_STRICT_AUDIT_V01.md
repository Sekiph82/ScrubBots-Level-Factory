## BLOCKING RISK: process count is not the number of real native solver calls

**Important strict finding:** published `SupplyOptimizer._run_prepared` groups up to **four** ranked candidate plans in one `solver.run(..., candidates=chunk)` Godot process, while the R08 master and audit criteria capped official native solver invocations at one primary plus at most one independent load-check. The R08 request contained four candidates. Godot's `solver_bridge.gd` loops over `req["candidates"]` and calls `solver.solve()` for each visited candidate until `stop_after_solved` or the list ends. **One bridge process does not prove one solver invocation.** A timed-out bridge with no `res.json` and no per-candidate checkpoint cannot reveal whether 1, 2, 3, or 4 internal candidate calls began. Do not assert a strict per-candidate count PASS or that the first candidate itself took the whole 60s. This is an **observability/scope deficiency**, not evidence that more than two calls actually happened. Subsequent one-source attempts must send exactly ONE real candidate per bounded native process and log actual start/finish identity and number, enforcing a global maximum before execution.

Other engineering limitations for future LF reuse:
- `pinned_game_source.py` hardcodes a single game `PINNED_MAIN_SHA` / tree SHA / manifest SHA / original one-source identity; this correctly freezes R08 evidence, **but requires new tracked edits whenever game `main` advances and does not yet represent reusable generic LF current-main authority for 100-level Family APK**. Future implementation should carefully parameterize verified attestation with immutable per-version snapshots and separately check latest main before publication; do not weaken source hashing or turn the old R08 snapshot into fake current main.
- `scrubbots_solver.py` emits `_runner` only on completed responses; on timeout it reports reason/job path, without a checkpointed partial per-candidate progress record. Native bridge only reports candidate completion. Existing saved request/job evidence may be inspected **read-only**; do not run a second solve to reconstruct an already failed attempt.

This must be addressed before any claim of actual R2 family shipping readiness, not bypassed.
